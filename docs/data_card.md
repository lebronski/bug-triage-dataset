# Карточка данных

## Назначение

Сырые (ещё не размеченные) данные для обучения и проверки системы
автоматической сортировки баг-репортов. На следующих этапах (лабораторные
работы 2–6) они размечаются в Label Studio: классификация репорта по
компоненту и критичности, выделение сущностей (`EXCEPTION`, `CODE_LOCATION`,
`ENV` и др.), рамки на скриншотах, расшифровка аудио. Правила разметки —
в [аннотационной схеме](annotation_schema.md), сами аннотации — в `annotations/`.

## Текст: `data/text/bug_reports/*/*.json` и `bug_reports.csv`

| Поле | Тип | Описание |
|---|---|---|
| `report_id` | str | `<проект>-<issue_id>`, совпадает с именем файла |
| `category` | str | одна из 10 категорий (предразметка по ключевым словам заголовка) |
| `component_hint` | str | компонент системы, соответствующий категории |
| `source_project` | str | spark, hadoop, hbase, cassandra, firefox, thunderbird, seamonkey, vscode |
| `tracker` | str | Apache Jira / Mozilla Bugzilla / GitHub Issues |
| `issue_id` | str | идентификатор в источнике (для Jira — внутренний числовой id из GitBugs) |
| `url` | str/null | ссылка на исходный репорт (для Bugzilla и GitHub) |
| `summary` | str | заголовок репорта (англ.) |
| `description` | str | текст репорта, 200–4000 символов, может содержать stack trace и код |
| `priority_original` | str/null | приоритет в трекере как есть (`Major`, `P1`, `Urgent`…); у VS Code и части Mozilla — нет |
| `severity_prelabel` | str/null | приоритет, приведённый к шкале Blocker/Critical/Major/Minor (предразметка) |
| `status`, `resolution`, `created`, `affects_versions` | str/null | служебные поля трекера |
| `license` | str | лицензия записи |

Правила отбора: описание 200–4000 символов; исключены автоматические отчёты
CI о нестабильных тестах (`Intermittent`, `perma`, `TEST-UNEXPECTED`) и
тестовые клоны; не более 3 репортов из одного проекта на категорию.

Известные ограничения: категория присвоена по ключевым словам заголовка и
может быть неточной (например, репорт про «Payment Request dialog container
styles» по смыслу ближе к вёрстке); тексты на английском; распределение по
приоритетам не сбалансировано, так как в трекерах преобладает `Major`.

## Текст: `data/text/logs/*/*.log` и `logs.csv`

Строки исходных файлов LogHub `<Система>_2k.log`, отобранные регулярным
выражением категории (не более 40 строк). В `logs.csv` указаны исходный файл,
выражение и диапазон номеров строк, поэтому выборку можно повторить.
Для категорий `payment`, `database`, `localization` подходящих логов в LogHub нет.

## Изображения: `data/images/screenshots/*/*.png` и `images.csv`

PNG, 1280×800 (десктоп), 780×1520 (мобильный вид 390×760 при масштабе 2×) или
1100×640 (терминал). В `images.csv`: описание дефекта, URL или команда,
которые воспроизводят дефект, и то, что фактически наблюдалось (код HTTP,
код сетевой ошибки Chromium, последняя строка вывода программы).

## Аудио: `data/audio/voice_reports/*/*.wav` и `audio.csv`

WAV PCM 16 бит, моно, 16 кГц, 11–17 с, полоса 200–3800 Гц (имитация
телефонного канала). В `audio.csv`: голос espeak-ng, темп и эталонный текст.
Записи синтетические: интонация и произношение отличаются от живой речи, что
нужно учитывать при оценке ASR.
